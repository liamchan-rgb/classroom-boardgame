# 课堂桌游：美术与UI设计标准 v1

日期：2026-10-12。对象：另一个设计对话、后续SwiftUI实现与素材制作。

本文件是第一轮设计提案和交接标准。玩法以原需求为准；视觉方向可由教师在设计对话中调整，不把建议风格当作已确认审美。教师已反馈v0.7无问题，当前具备独立规则库与双画面基础。

## 1. 目标与分工

产品是教师个人使用的原生iPad课堂桌游。学生口头讨论，由教师操作；最多6名学生加1名主持人角色。教师讲课时可以随时暂停、发奖、切绘本和纠错。

- 本开发对话：继续阶段2最小PVE、规则接入、真机集成与GitHub构建。
- 设计对话：美术方向、双画面布局、组件、状态设计、分层资产与标注。
- 规则依据：`docs/课堂桌游_需求设计_v1.md`；实施顺序：`docs/课堂桌游_开发步骤_v1.md`、`实施计划_v2.md`。
- 当前实现：`native/Packages/GameCore`、`native/ClassroomProbe`；初始数值唯一来源为GameCore的 `initial-content.json`。

设计先交页面与素材，正式接入由开发对话完成。设计对话如使用仓库，修改范围限 `design/`；可在单独分支或独立工作区交付。双方不能同时改同一份App源码、规则JSON或构建工作流。

## 3. 推荐视觉方向

**明亮、温暖的绘本式轻奇幻桌游。**

环境可用森林、遗迹、石路和魔法；角色轮廓清楚，适度夸张，有趣但不过度幼龄化。职业有不同武器与服装轮廓，怪物有明显形状差异。小头像下仍能认出职业或怪物。

画面用奶油白、深墨绿与少量金色；纸感/木质/石质只作轻装饰，数字和文字落在干净面板上。教师端更简洁，公开端可增加插画和表现力，两端共享颜色、角色与图标语言。

避免写实血腥、过暗背景、满屏发光粒子、密集花纹和依赖细小文字的游戏HUD。学生年龄尚未指定，本提案优先清楚、有趣与可读性。

第一轮提供同一方向的两种轻微变化，例如“森林绘本”与“清爽魔法学园”，各含一组角色/怪物样稿、组件样稿和双画面小预览。先用样稿确定方向，再批量制作全套资产。

## 4. 设备、画布与尺寸

| 画面 | 设计基准 | 交付预览 | 布局要求 |
|---|---|---|---|
| 教师iPad | 横屏1366×1024逻辑点 | PNG 2732×2048 | 2021款12.9寸iPad Pro；尊重系统安全区域，不把状态栏/键盘区域画进内容 |
| 电视公开屏 | 1920×1080设计单位，16:9 | PNG 1920×1080；高分辨率可另交3840×2160 | 根据实际外屏尺寸缩放；四周保留约5%关键内容安全区 |
| 外屏适配检查 | 1440×1080，4:3 | 一张适配稿 | 调整区域比例与卡片布局，不拉伸角色、裁掉地图或隐藏必要字段 |

电视的实际分辨率尚未单独确认，1920×1080是设计基准，不是设备检测结果。画布尺寸不成为代码固定布局。

教师端主要文字17—20pt、说明不低于15pt；标题24—30pt。所有常用点击区域至少44×44pt，主要行动按钮建议高52—56pt。间距统一8/12/16/24/32pt，面板圆角16pt、按钮12pt。

公开端以1920宽设计稿为基准：正文/角色数值26—32单位，姓名28—34，主要提示40—48，当前角色/倒计时48—64；必要辅助文字尽量不低于24。最终以课堂实际最远座位核对，不只在iPad近距离缩略图上检查。

默认使用iPad系统字体、中文系统回退和等宽数字。字体、图标和素材必须可本地打包；附授权来源。运行时不使用在线字体或图片服务。

## 5. 双画面信息与布局

### 5.1 教师游戏屏

建议采用顶部状态、中央地图、侧边对象与操作面板、底部课堂快捷操作。

- 顶部：探索/PVE/PVP等当前阶段、当前轮、行动者、剩余时间、暂停状态、公开屏连接状态。
- 左侧：玩家列表，显示生命/护盾/AP；奖励对象可多选；主持人明确标识。
- 中央：地图、道路、玩家/怪物、路径和合法目标提示。战斗沿用当前地图。
- 右侧：当前行动者信息，移动/普攻/3职业技能/道具/救援/结束回合。技能明确标AP费用、射程、剩余次数及不可用原因。
- 底部：常用奖励组合、暂停/继续、绘本切换、撤销与更多后台操作；奖励栏始终写明对象及实际变化。

1366宽参考布局：外边距24、左栏224、右栏320、栏间距16，地图取剩余宽度；可调整，不要求固定三栏。常用操作应在一屏可达，不靠整页滚动寻找行动按钮。详细编辑、背包和历史可以独立滚动。

**“当前行动者”和“奖励对象”必须分开。** 当前行动者用“行动中”徽章，奖励对象用勾选框及“奖励对象：…”说明；选奖励对象不能暗示切换回合。两者为同一人时同时显示两个标记。

普通行动通过“选动作 → 选合法目标/路径 → 明确行动按钮”执行一次。只选择和查看详情不扣点、不掷骰、不重置时间。没有奖励对象时按钮不可执行并给出就地说明；常规发奖和攻击不增加确认弹窗。

### 5.2 电视公开游戏屏

- 地图是主体，显示已揭示节点、道路、可公开单位与行动焦点。
- 顶部当前轮、当前角色、倒计时/暂停，固定队列清楚可辨。
- 玩家状态区最多7人，显示姓名、当前/最大生命、护盾、AP、金币、积分与队伍；主持人标识。
- 骰子/结果区显示公开结果、目标和简短资源变化；仅展示已提交操作。
- 排行榜由教师决定何时展示；结算分别显示战斗胜者与积分排名。

公开屏没有教师编辑按钮、奖励多选框、备注、未揭示怪物/奖励、模板掉落概率和调试信息。未知地点只显示轮廓或问号，不用角色插画或装饰提前暗示Boss/奖励。

### 5.3 绘本双画面

教师端：页面预览＋对应备注＋页码/翻页＋课堂奖励和暂停。备注可独立滚动，键盘输入不触发游戏快捷键。

公开端：绘本等比完整显示＋简略玩家状态条。每人必须显示姓名、当前/最大生命、护盾、金币、积分、队伍；**不显示AP**。7人场景也保留全部必要字段，不能靠缩小到难以辨认来塞满。

绘本保持原比例，留白可以，页面文字不可被裁切。装饰不得覆盖PPT内容；页面不强制套用游戏配色。备注、输入光标和滚动位置不进入公开画面。

## 6. 组件与状态标准

| 组件 | 必须交付的状态或信息 |
|---|---|
| 玩家/怪物卡 | 普通、当前行动、奖励选中、合法目标、受击、倒地、主持人、下一轮才能行动；状态可叠加 |
| 技能/道具按钮 | 可用、选中、AP不足、次数耗尽、无合法目标、阶段不允许；费用/次数可读 |
| 地图节点 | 已探索、未知轮廓、当前地点、路径经过、敌人地点、奖励已领取、同地点多人/多怪物 |
| 队列 | 当前、已行动、倒地跳过、新加入下轮可行动；先后固定，不因动效自行重排 |
| 资源 | 生命与护盾分开；AP、金币、积分使用图标＋数字/文字，队伍用名称＋颜色/标记 |
| 计时/暂停 | 决策计时、手动暂停、绘本/编辑/历史暂停、全员倒地、怪物行动；暂停时显示保留时间 |
| 操作结果 | 普通伤害、盾吸收、自然20、治疗、救援、奖励、掉落、战斗结束；一次完整结算的一组结果 |
| 历史/撤销 | 动作、对象与结果摘要；回退范围及恢复状态预览；显示原骰子，不重新抽取 |
| 文件/内容 | 空资料、加载、导入失败、保存失败、恢复后暂停、断连重连；使用教师能理解的提示 |

颜色不能独自承担状态含义：倒地要有文字/姿态，选中要有边框/标记，队伍要有名称。生命与护盾不合并成一条无法区分的数值；自然20由明确文字和图标强调。

原需求的初始键位为可修改建议，UI可标注对应按钮；完整绑定在阶段5实现。当前v0.7只实现数字选择、G奖励和空格暂停等阶段0验证键，不要在设计演示中声称所有快捷键已可用。

## 7. 动效与反馈

按钮反馈约120—180ms，面板约200—250ms，资源变化约300—450ms；骰子和自然20主要表现尽量在600—900ms内结束。提供减少动态效果/立即显示结果的布局。

动效只显示已确定的骰子和结算结果，不产生第二次掷骰、伤害、奖励或掉落。播放/跳过/重复查看效果不会改游戏状态。动画和怪物行动不消耗学生决策时间，计时由规则状态控制。

受击采用短暂闪色/小幅位移，倒地用低饱和和姿态变化，救援用柔和亮起；保持名字和数字可读。首轮不制作完整骨骼动画或大量特效，静态头像、状态和简单转场足以支持PVE试课。

## 8. 初始设计令牌

机器可读文件为 `design/design-tokens_v1.json`，设计稿引用相同语义名称。以下颜色是第一轮建议；文字/底色组合需按第10节检查对比度。

| 名称 | 建议值 | 用途 |
|---|---|---|
| background | #F5F1E8 | 暖白主背景 |
| surface | #FFFFFF | 信息卡片 |
| ink | #183B36 | 主要文字 |
| muted | #526B64 | 次要文字 |
| primary | #176B5B | 主操作，配白字 |
| accent | #B76A08 | 当前焦点和少量金色装饰 |
| danger | #B93838 | 错误/危险/生命告警，配文字或图标 |
| shield | #315E9C | 护盾 |
| action | #6650A4 | 行动点 |

队伍采用蓝、橙、紫等标识色，并同时显示名称。队伍颜色与生命/护盾/AP的语义分开；队伍数量可变，不能把界面写成永远只有两队。

## 9. 美术资产与交付

### 9.1 制作范围和批次

| 批次 | 素材/页面 | 优先级 |
|---|---|---|
| A | 风格样稿、教师战斗/公开战斗双画面、组件板、7人布局 | 立即开始 |
| B | 冒险者/游侠/魔剑士/龙骑士；史莱姆/狼/弓手/石像/巨魔/魔龙；状态资源图标 | 阶段2 |
| C | 12普通物品＋6套装部件；背包、商店和套装组件 | 阶段3 |
| D | 5类地点、迷雾/道路/地图装饰、探索适配 | 阶段4完善，小地图提前用基础节点 |
| E | 教师编辑、历史、绘本/资料、PVP、排名和胜者表现 | 阶段5—7 |

头像描绘职业/怪物模板，姓名、队伍、生命数字由App叠加。同职业可以有多个玩家，不用独占某一个角色槽；头像预留颜色/边框/标记区分，不硬编码学生姓名。

### 9.2 素材格式

- 职业/怪物头像：1024×1024透明PNG，sRGB；主体不裁切，安全留边约10%，全套裁切比例一致。
- 物品与地点：512×512透明PNG；物品单独主体，无文字、价格、数量和卡片边框。
- 自定义小图标：可编辑SVG源文件及256×256透明PNG；可另交可用于Xcode的矢量PDF。系统常规控件优先使用SF Symbols，不必为每个按钮画图。
- 装饰背景：按目标比例导出，分开地面/装饰层，不烘焙地图节点、连线、单位、文字和HUD。只有非关键信息背景可裁切适配。
- 预览整页可以是合成PNG，但App需要可独立使用的各层素材；图上的中文、名字、数字都应保留为界面文字。
- 每项资产提供文件名、绑定ID、尺寸、透明性、风格版本、来源/授权和状态。`asset-manifest_v1.json` 是待制作清单，不代表现有素材已经生成。

素材名使用ASCII小写与下划线，例如 `class_adventurer_portrait`、`monster_ruin_dragon_portrait`、`item_revival_stone`。绑定到已有模板ID，不能用中文文件名或数组顺序作为程序唯一绑定。

### 9.3 设计对话交付结构

```text
ui-art-delivery/
  README.md                  # 方向、覆盖页面、未完成项、授权信息
  design-tokens.json         # 对本标准令牌的修订
  asset-manifest.json        # 绑定ID、文件、尺寸、授权、状态
  previews/                 # 双画面、7人、长名、4:3与主要状态
  assets/                   # 独立透明PNG等运行素材
  sources/                  # 可编辑源文件；有则提供
  annotations/              # 尺寸/布局、组件状态、交互与适配说明
```

首次至少交教师战斗屏、电视战斗屏、组件状态板和风格样稿；进入完整批次后再补绘本双画面、背包/商店、地图、历史与结算。不接受仅给一张漂亮整页图片作为全部可接入交付。

## 10. 设计验收场景

1. 双画面同一状态：教师端选奖励对象/编辑备注，公开端不出现这些操作或私有内容。
2. 7角色＋多怪物：名字、生命、护盾、队伍可读；同一节点拥挤时可展开/汇总，不盖住行动路径。
3. 长姓名：至少测试12个汉字及24个英文字符；Teacher可查看完整名字，公开端可合理换行/缩写，仍能识别人。
4. AP0、技能耗尽、距离不足、未选目标：按钮有明确状态和原因；不只降低透明度让人猜。
5. 当前行动者A、奖励对象B/C：操作结果与两个选中标记能清楚区分；AP触顶显示实际增量。
6. 自然20群攻：3目标一起倒地，Boss护盾不能挡；附带自疗、掉落、积分作为同一已提交结果显示。
7. 救援13生命上限恢复7：明确“第2轮可行动”；新加入怪物亦可表达下轮资格。
8. 手动暂停后开绘本/历史并返回：保留暂停与剩余时间，不能画成回游戏就自动运行。
9. 7人绘本公开状态条：六个规定字段完整，AP不显示，PPT内容不裁切；长备注独立滚动。
10. 未探索Boss/奖励节点：公开预览里不能通过底图、头像、图标或提前日志猜出内容。
11. 排名并列1、1、3，战斗胜者和积分冠军分别展示；多阵营提前结束需要明确选择。
12. 在1920×1080和1440×1080公开稿以及实际电视上核对：必要文字清楚，不掉字段、不变形。

普通文本对比度建议至少4.5:1、大字至少3:1；队伍/状态有颜色以外的标记。主要操作可触摸，全部常规快捷操作有屏幕等价按钮。减少动态效果后信息仍完整。

## 11. 开发对接边界

现有 `PublicGameSnapshot` 支持公开阶段、轮次、当前角色、队列、时间、单位、节点、道路和骰子。正式公开战斗日志/结果摘要等需要后续公开投影补充；设计可以预留，不能直接接入私有教师模型。

资产清单的模板ID与现有GameCore数据对应；添加视觉字段不得修改生命、AP、价格、射程、技能次数或掉落概率。SwiftUI读取设计令牌和独立素材，原规则库继续作为唯一结算来源。

设计对话用演示数据验证布局，开发对话负责把页面接真实状态、保留离线运行和备注隔离，并在Xcode27及真机验证。纯设计文件不触发IPA重编译；UI/素材正式接入时再编译新版本。
