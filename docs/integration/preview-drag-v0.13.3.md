# v0.13.3/build17 · 教师960×540/30Hz分层回传与拖动地图

用户要求教师端提到30fps并提高分辨率，地图恢复之前demo的拖动方式。本轮依此覆盖v16辅助预览640×360/15Hz配置，绘本两项仍只记录。

## 回传与开销

教师回传配置为960×540、30Hz目标，游戏逻辑画布1280×720和电视60Hz目标保持。GPU缩图、单一在途缓冲、后台utility读取CGImage与可见性暂停仍在。新增分层回传：地图CGImage由SwiftUI直接显示，不在主线程每帧重新绘入整幅UIImage；源游戏控制器的透明UIView公开层另行缓存，地图静态HUD仅脏时最高10Hz更新，战斗/骰子演出按30Hz更新。公开行囊/结算仍使用同一固定画布，教师权限/备注/按钮不进入捕获。

完成的新地图帧直接推送，定时器只补加载/暂停中的UI变化；交付时钟和采样时钟保持阶段，容忍略早的vsync，挂起后丢弃旧帧不补队列。只更新画面，不推进第二份规则、AI、计时或随机数。裸GPU像素配置预算为62,208,000字节/秒；不把该数值当成设备耗时或实际稳定帧率。960×540和30Hz为实现配置，实际iPad/电视性能由用户安装复核。

## 拖动与缩放

已对照原experiment GameViewController.panMap/pinchMap及GameScene.panBy/setZoom：沿用相机平移方向、边界限制和缩放锚点；恢复双指拖动/双指捏合，并允许单指、鼠标按住拖动。在教师实际画面上拖动平移视野，点击道路仍移动人物，点建筑仍选节点；拖动抬手不发送走路命令。手势先消除等比留边缩放，平移用向量换算，缩放围绕手指位置，跨电视比例/全屏不改内部坐标。

使用教师端独立UIKit手势层，地图区域拖动优先于外层ScrollView；地图以外仍正常滚后台页面。pan/pinch可同时识别，tap等待pan/pinch失败，起点在黑边/只读预览卡片/非法状态不接收；拖出画面后继续跟踪，不让起点跳到当前指针位置。控制层只在教师端，不使公开电视可操作。缩放和拖动均调用原场景相机接口，不扣移动条/AP，不重投或重生地图。
