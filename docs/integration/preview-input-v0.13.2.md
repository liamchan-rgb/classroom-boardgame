# v0.13.2/build16 · 教师预览开销与点击修复

用户反馈v0.13.1交互卡顿、点不动。本轮通过源码检查确认重开销路径和输入缺口，未运行App/模拟器/实机，未量测用户设备CPU/GPU或帧率。

## 修正

- 旧版教师回传在主线程以最高30Hz对1280×720整游戏UIView重新栅格化，并在主线程复制GPU buffer/构造CGImage。现在GPU先缩为640×360（战斗分区同比缩小），像素复制和CGImage构造移到独立utility队列，公开UIView的必要合成仍在主线程，以半分辨率、最高15Hz进行。每次至多一个GPU回传/后台拷贝在途，未完成时丢弃采样，不堆积任务；相同Metal帧且无战斗演出时不重复合成。主游戏逻辑画布1280×720、电视原生渲染60Hz目标保留。
- 640×360×4×15的理论裸像素预算为13,824,000字节/秒，旧1280×720×4×30为110,592,000，前者为1/8。这是配置预算，不是设备实测耗时、带宽或性能提高8倍。教师预览因此分辨率/采样较低，电视游戏素材与分辨率不降低。
- 只有接电视且教师游戏预览可见、App前台、非绘本且没有私有对话框时才进行回传。用视图可见性订阅区分全屏/嵌入预览，不恢复简略地图或创建第二引擎。
- 原后台每150ms无条件发布revision，导致整控制页反复计算布局和按钮校验。现在只在个人/队伍会话、历史回执、移动显示、暂停、当前回合、动作忙碌/准备状态等实际变化时发布；AI/超时计时照常推进。
- 原全屏页仅显示只读PublicSurface，遗漏TeacherGamePreview输入层；现全屏也接入同一教师手势和坐标换算。教师全屏返回/收起预览按钮留在教师窗口，不进入公开捕获。
- 原canvasTap仅接受exploration，点战斗建筑打开encounter预览后后续地图点击被静默丢弃；现在encounter状态允许在预览外的真实道路继续移动。预览卡片内部仍只读，可用“收起预览”返回地图；非法面板/忙碌/载入中给出提示。建筑命中、固定画布和权限隔离保持。

## 检查范围

17项后台/画布/预览专项通过，新增覆盖：打开怪物预览后教师导航返回地图且不改变战斗RNG；后台回传像素预算上限与独立固定画布；隐藏、本机、绘本、后台、私有弹窗时禁用回传。全屏输入绑定、工作队列、单个在途回传与公开端隔离做源码审计；实际触摸/流畅度不在此声明验收。
