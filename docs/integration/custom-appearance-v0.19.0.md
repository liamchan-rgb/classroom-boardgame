# 人物自定义 · v0.19.0/build24

用户要求将 experiment 新发型、五官和双B衣装接入人物自定义。本轮只移植外观资源与呈现/存档字段，不覆盖课堂规则、地图、教师权限、组队或绘本。

## 入口和使用

教师游戏“管理 → 人物档案/行程槽 → 人物档案”，选择当前玩家，分别选择六款发型、四套五官、衣装。男女标签只用于样式推荐，可以自由混搭。衣装增加星辉甲B天仪礼甲、龙纹甲B龙翼巡游甲；“跟随实际护甲”及原基础衣装/皮甲/符文甲保留。预览后点“应用到当前角色”。保存人物槽可供新行程读取，亦支持导入导出；P7老师使用同一编辑区。公开画面只显示应用后的角色，不显示教师选择器。

`PlayerAppearance` 新增可选 `hair`、`face` 稳定ID；原 `body/outfit` 不改名，旧档缺字段解码为nil，原存档格式版本保持。新增值进入严格白名单，整笔档案操作先验证；不改职业、数值、金币、背包或实际装备。原人物槽、行程槽、历史回退和批量导入导出通过Codable保存同一完整选择。字段没有按性别/武器重选头部的分支。

## 固定美术来源和组件

experiment 来源 `13cbe2e250a74a1a8e5c4a0dd026c866fd2cdfa8`。F1使用r4原正面盖耳版本，不能回到r3整体短发。源5406个依赖逐一核对Git blob与SHA256；本轮新派生130个图像名/260资源文件，加custom-appearance.json，并更新hero-gait.json。原全局基线175c7dfc保留，meadow-port-provenance.json逐文件记混合来源，资源总数829。

行走：原八向104姿态、13列、120ms循环和起停时钟保持。30对身体/衣装/武器图集、六对近侧前景袖/手层、八对头发与六对五官。换装时才合成当前负载，地图SpriteKit与Metal阴影使用相同像素，不预载所有组合，不逐帧切换人物形状。正左/右近侧袖子沿原drawOrder盖在头发末梢前；其余方向保持原层次。背剑/弓/重剑/权杖从实际装备驱动。预览、背包、地图读取同一记录。

战斗：原四武器、七状态。新发型/五官按原登记替换独立头部；弓的canvas-baked状态只给新rest头部应用一次torso变换，禁止重新变换已烘焙旧head tile。双B沿原皮肤、裤腿、手和武器，用已审核通用衣物及弓独立贴身材质，不把行走服装塞进战斗。战斗影子在换头时清缓存并更新。原发型/脸作为独立选择保留，并用相同已建立登记对应行走视角；没有新增体型。

## 检查与交付

新增10项Swift专项：旧档解码、独立混搭、非法ID原子拒绝、换一个玩家不影响其余人/装备数值、新行程/完整行程/人物槽持久化、装扮与属性隔离、缓存键包含头部。全量核心413项零失败，绘本ProbeCore6项另核。

`native/tools/build_custom_appearance.py <SHA-verified-input-cache> <experiment-checkout>`派生实际App组件。`check_custom_appearance.py`核对所有829资源、PNG CRC、组件引用；`review_custom_appearance.py <experiment-checkout>`读取App内实际PNG进行4992个全身比较，允许最多2级RGBA整数合成舍入，不把容差说成逐字节相同。战斗图像与源稿像素一致，未改动作JSON。主线程看全身总览、实际GIF抽帧，机械组合穷举不等于逐张目检。

正常GIF与整身图在custom-appearance-review-v0.19.0/；GIF是实际行走组件及既有战斗采样器的离线全身合成，不是UIKit截图、触摸/设备性能证明。遵守用户约定，不启动App、模拟器或实机；安装、电视与性能由用户反馈。实际设备Release构建、包检、完整公开GET与可恢复存档另记custom-appearance-v0.19.0-build.json及archives索引，结果到达前不声称已完成。
