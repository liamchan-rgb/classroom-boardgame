# v0.17.0/build22：人物与行程存档导入导出

本轮执行上次交付后的第一步：人物档案、完整行程的手动导出导入。行程与历史分类筛选留到下一步；没有新增美术或另建游戏引擎。

## 教师使用

教师游戏右上“管理 → 人物档案 / 行程槽 / 历史 / 老师参战”，或教师绘本“存档与历史”，窗口右上新增“导入导出”。每个人物槽、行程槽也有单独“导出”按钮，直接预选该槽。所有文件窗口均由教师私有SwiftUI宿主打开，不放进公开游戏/电视捕获。

**导出：** 可勾选一个或多个人物/行程槽，生成一个JSON，再通过系统文件保存窗口选择位置。保留槽标题、原保存时间和完整内容，导出不会改写槽位；取消文件窗口没有游戏副作用。这里只导出已保存槽：要备份当前游玩进度，先在行程页保存到槽位。人物条目严格保留原姓名/现有外观模型，不引入职业/数值/装备/背包。完整行程沿用原MeadowCampaignSave，保存地图、成员、背包、战斗队列、骰子状态、各队移动条、道路、镜头和历史。

**导入：** 从“文件”选JSON；先校验再显示来源、人物/行程数量、逐项勾选与目标槽。默认目标为来源槽号，可改成其他合法槽。现有目标标题/损坏提示可见，同类条目不能指向同一个目标；人物槽与行程槽可以同号。点击“校对并导入”后，确认框逐项列出来源→目标和覆盖数量。导入只改所选槽，不更改正在玩的行程；返回上一页点击“读取”才会应用。

**旧文件：** 接受新版统一包，以及旧人物槽JSON、人物档案JSON、行程槽JSON、原campaign-v1地图工作档。旧单文件默认来源槽1，仍可在预览改目标。识别到新版format但版本不支持时明确拒绝，不能按旧文件误读。空包、重复槽、超界槽、错误外观/规则/地图、损坏JSON均拒绝，原槽保留。

**覆盖与中断恢复：** 批量导入前读取全部目标原始字节并保存本机ImportBackups日志，再持久化pending-import标记，之后才逐文件原子写入。写入失败立即恢复整批原槽；若应用被杀或设备中断，下一次任何槽读写先回滚pending批次，完成后才暴露槽数据。原本为空的槽会移除中断生成的文件；损坏目标的原始字节也保留。恢复本身失败时保留日志并阻止槽读写，避免返回半份导入。导入页可选择最近20份覆盖前备份，先进入同一预览再恢复；旧记录不删除。单份已完成备份损坏仅单独列错，不遮住健康槽。原始文件已损坏的备份会报错并保留字节，不声称能够修复原损坏。

## 文件与性能

格式名classroom-meadow-save-transfer，version1，exportedAt，profiles/campaigns数组；每项含来源slot和原MeadowSaveSlot。最多12人物+8行程，不存文件路径、权限或账号；目标文件名由受限类型/整数槽号生成。文件上限128MiB，读取前检查大小并按1MiB分块限额；大行程可拆分导出。JSON读写/校验/批量事务在后台Task处理，私有窗口显示处理中并禁用重复操作/关闭。安全作用域按系统文件选择器开始和结束，取消/错误可见，不自动上传任何教师设备资料。

原12/8槽、工作档、Recovery行程备份、历史回退、P7老师入口与公开布局保持。顺带把人物装扮“蓝衣”标签改为“基础衣装”，避免林间绿衣款式下名称不符；内部旧blue值保持兼容，未改美术。
