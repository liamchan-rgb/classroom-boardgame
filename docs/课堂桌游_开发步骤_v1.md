# 英语课堂电子桌游：分阶段开发计划 v1.0

版本日期：2026-10-12（北京时间）  
依据：课堂桌游_需求设计_v1.md。  
本文件用于后续在Codex中开发，当前没有创建应用或确定技术栈。

## 1. 如何使用这两份文件

先把两份Markdown文件放进开发项目，或作为附件提供给Codex。需求文件定义“做什么、怎样算对”，本文件定义“先做什么、如何验收”。

每次给Codex一个里程碑范围。完成后保留代码、验证结果和问题记录，再进入下一项。已确认规则按原文实现；补充默认按原文落地并保持可配置；只有改变硬性要求或出现不可消除的技术阻碍时再讨论范围。

不要一开始同时开发完整后台、PPT渲染、随机地图、PVP和存档。首先验证决定产品能否满足课堂要求的设备能力，再建立可独立验证的规则计算。

### 开发输入

| 已有 | 阶段0还需在后续开发会话提供 |
|---|---|
| 完整规则与初始数值 | 实际iPad型号、系统版本 |
| 玩家最多7人、实体键盘操作 | 无线投屏接收设备与实际连接方式 |
| 本地静态PPTX与教师备注目标 | 一份真实绘本PPTX，含有代表性的备注、文字和图片 |
| 无Mac、个人使用、全离线要求 | 可用于构建、安装和更新的实际设备条件 |

这些输入用于后续技术验证；本次需求交付不依赖现在取得文件或设备。

## 3. 阶段0：验证设备与技术路线

### 0.1 最小验证内容

只做能力验证样例，不先制作完整游戏。

1. 在教师实际条件下明确应用的运行、安装、更新路径，列出是否需要Mac、其他电脑、账号或费用。
2. 显示一个教师界面，包含一段测试台词和控制按钮；公开屏显示另一幅简单页面。
3. 使用实际无线投屏接收设备，检查打开备注、切换页面、弹出菜单、断连重连时公开屏是否始终不出现私有信息。
4. 断网后从本地导入代表性PPTX，处理所有静态页和演讲者备注。
5. 检查页面比例、图文位置、字体可读性、页码、空备注与长备注。
6. 验证本地文件导入导出、键盘事件、应用暂停与恢复。

“能够显示PPT图片”不等于“能够正确离线导入PPTX”；“教师端看不到公开屏”不等于“台词未投屏”。需要分别验证。

### 0.2 必须交付的验证记录

| 记录 | 内容 |
|---|---|
| 技术路线 | 运行平台、语言、框架、构建与安装流程；依赖清单 |
| 双画面实测 | 使用设备、连接方法、实际教师／公开内容、断连行为 |
| PPTX报告 | 每页成功／失败、备注对应情况、不支持对象、处理时间 |
| 离线测试 | 断网条件下完成哪些操作，是否存在外部服务依赖 |
| 安装与成本 | 实际使用条件与成本，不把未知写成“永久免费” |
| 问题清单 | 阻碍、证据、影响的需求、可讨论的替代方案 |

可在项目中记录为“技术验证.md”。没有真实设备证据时，明确标记“待真机验证”，不能把模拟器成功写成全部通过。

### 0.3 完成条件

- 教师私有备注与公开画面能独立显示并通过真机检查。
- 实际PPTX能离线处理页面与备注，或明确报告尚不能通过的具体内容。
- 在无Mac的实际条件下有可重复的安装和更新方案。
- 选型不会依赖未同意的在线转换或强制订阅。

若硬要求不能满足，先提供具体可审阅的限制和替代方案，讨论该项需求后再继续依赖它的实现；独立的规则整理无需重开讨论。

### 可复制到Codex的任务

```text
读取“课堂桌游_需求设计_v1.md”和“课堂桌游_开发步骤_v1.md”。
只执行阶段0。教师使用iPad、实体键盘、无线屏幕镜像，无Mac，需要全部本地离线，并要求PPTX演讲者备注只出现在教师画面。
先检查实际开发与安装条件，再制作最小能力验证样例，验证独立公开画面、离线PPTX页面与备注导入、本地文件和键盘。
不要先实现完整桌游。不能验证的项目明确标记，记录实测证据、限制、费用和候选路线。
阶段成果写入“技术验证.md”，据此确定后续技术栈。
```

## 4. 阶段1：规则计算与数据

### 1.1 建立领域数据

- 模板与本局实例分开，当前生命与最大生命定义分开。
- 玩家、队伍、怪物、地图、技能、装备、掉落、计时、战斗队列、操作记录分别建模。
- 将需求附录A—D录入可校验的初始数据文件，不在界面代码中散落数字。
- 私有备注与公开显示数据分开。
- 保存格式带版本；随机来源可控制，便于验证与历史回放。

### 1.2 实现核心计算

先不依赖UI实现：

1. 行动点补足、上限、费用、手动结束保留、超时清零。
2. 节点最短路径、射程与移动消耗。
3. 单体／节点群体攻击、同一次群体掷骰、自然20穿盾秒杀。
4. 生命与护盾、治疗、增益持续时间、倒地、救援、下一轮才能行动。
5. 固定队列、轮次、已行动标记、中途加入的可行动轮。
6. 自动加分的来源与归属、队伍实时总分、并列。
7. 暂停原因叠加、剩余时间恢复。

### 1.3 建立完整操作结算

每次操作按以下顺序：

1. 验证角色、阶段、目标、射程、资源；
2. 捕获操作前状态和随机状态；
3. 扣消耗，掷骰并应用全部效果；
4. 处理全部倒地／战败、掉落、积分；
5. 检查战斗胜负与阶段变化；
6. 若战斗仍进行，处理行动点耗尽与队列推进；
7. 一次提交状态、一次记录历史、触发一次保存。

动画、列表重绘和恢复界面只展示已提交结果，不能再次发奖励。

### 1.4 有意义的自动验证

固定骰子及随机值，覆盖AC02—AC06、AC11—AC19、AC30—AC33对应计算。重点验证同一操作的所有变化一起发生、失败操作无部分消耗，以及重复展示不会重复结算。

不必给每个低风险按钮编写镜像测试；规则组合、事务一致性、暂停与持久化边界更重要。

### 完成条件

规则计算可以在没有完整界面的情况下独立运行；初始数据数量、技能与商品数值准确；关键组合验证通过。

### 可复制到Codex的任务

```text
依据需求与阶段0选型，只执行阶段1。
建立独立于界面的规则计算、模板/实例数据和完整操作结算流程，录入附录A—D初始数据。
优先验证行动点补足、固定队列、群体同骰、D20自然20、护盾、救援下一轮行动、积分归属、暂停原因叠加。
使用可控制随机值验证，不依赖真实概率碰巧抽中。给出实现结果和通过/未通过的验收编号。
```

## 5. 阶段2：最小PVE完整流程

### 开发范围

- 简单游戏屏幕：节点、单位、生命／护盾、当前回合、计时器。
- 支持1—7个玩家与少量敌人，教师选择对象并发起操作。
- 开战掷先攻、轮次补点、选择路径、普攻、技能、道具、救援。
- 固定队列中正常推进，怪物按照策略与优先级自动行动。
- 中途遇怪加入，敌人全部战败回探索，全员倒地暂停。
- 最基本的手动暂停／恢复和资源编辑。

先用小地图，不在此阶段实现随机地图编辑与完整绘本。

### 验证

用冒险者、魔剑士或龙骑士，配合史莱姆、弓手、巨魔完成一场战斗。再用可控D20结果验证Boss秒杀与群体倒地。

完成AC01、AC04、AC08、AC15—AC20等相关流程；每一轮、每次攻击只执行一次。

### 可复制到Codex的任务

```text
只执行阶段2，基于现有规则计算制作可操作的最小PVE流程。
包含教师选角色、移动/攻击/技能/道具/救援、计时、固定行动队列、怪物AI、中途加入、自动战斗结束和全员倒地暂停。
使用一张小地图完成端到端演示，界面清楚可操作即可。绘本与随机地图留到后续。
验证真实操作调用既有规则，不在界面另写第二套伤害或奖励逻辑。
```

## 6. 阶段3：装备、套装、掉落与经济

### 开发范围

- 个人金币、无限背包、1武器＋1护甲＋1饰品。
- 探索换装，战斗禁止正常换装。
- 常驻属性、2件／3件套装累加、套装主动技能。
- 套装技能次数不会因卸下重穿刷新。
- 同队资源转移与仓库存取，战斗个人背包限制。
- 教师手动打开商店，普通商品全上架，无限库存，固定买卖价。
- 全部怪物掉落逐项独立，六件套装逐件判定，最后击杀者获得。
- 怪物击杀分、救援分、事件分的基础积分账目。

### 验证

核对附录每项数字；穿齐星辉、龙纹检查完整属性；使用控制随机值触发多件掉落；交易失败不扣资源。

完成AC21—AC26；确认稀有套装不在商店出售但有回收价；默认护盾药水回收价7。

### 可复制到Codex的任务

```text
只执行阶段3，实现全部已确认商品、装备、两套套装、个人背包、队伍仓库、买卖和怪物掉落。
普通商品无限库存、探索不限位置购买、稀有套装只掉落或教师发放。所有掉落项独立，最后击杀者归属。
属性只从穿戴装备计算，2件和3件加成累加；最大生命变化不自动治疗，基础行动点增加不立即补点。
核对附录B—D，验证AC21—AC26并报告结果。
```

## 7. 阶段4：随机地图与探索

### 开发范围

- 总节点数输入，系统建议起点／战斗／Boss／奖励／空地点数量，教师可修改。
- 连通的随机道路、分叉和环路、随机地点内容，存下实际地图与生成种子。
- 按学生人数推荐怪物组合，教师确认，不改变怪物属性。
- 单节点替换怪物／奖励；开局前整图重生成。
- 起点、逐步揭示、共享地图信息。
- 探索多人同行，预检行动点，按经过道路收费，敌人处停止。
- 奖励事件到达自动结算，每次到达者各一份，整局一次。

### 验证

测试多种节点数量和生成种子，保证数量正确、连通、无坏边、起点无敌人。验证三人同行与稍后到达者的奖励，以及遇敌前实际距离扣点。

完成AC07—AC10、AC28相关流程。此阶段不额外建立任务卡、道路上锁或自动英语题库。

### 可复制到Codex的任务

```text
只执行阶段4，落实第5节地图生成和探索流程。
指定节点总数后建议类型数量，教师可改；道路和内容都随机，图必须连通。支持单节点换怪/换奖励和准备阶段整图重生成。
多人同行每人独立扣点，不足时不部分移动；第一个敌人节点停止并开战。奖励到达自动结算，同批各一份，后到不重复。
验证不同地图规模、可控生成种子以及AC07—AC10、AC28的相关状态。
```

## 8. 阶段5：教师后台、键盘与回退

### 开发范围

- 教师常用操作面板、单选／多选奖励对象与奖励组合。
- 本局即时编辑；明确“保存为模板”，避免误改全局。
- 修改队伍、资源、位置、怪物、队列、技能次数、商店与结束方式。
- 全套可自定义快捷键与屏幕等价按钮。
- 文本输入时不触发游戏快捷键，长按不重复发奖。
- 详细编辑／历史面板暂停，关闭恢复此前状态。
- 连续撤销、历史回退、完整操作前后状态与随机结果记录。

### 回退重点

攻击、移动、奖励、交易、救援、队伍调整、后台修改都要以完整操作回退。首次领取事件的完成标记、地图揭示、技能次数、自动结束阶段也属于操作的一部分。

先提供快照或足够可靠的操作前后数据，不必为首版追求复杂事件存储架构。实现方式可以简化，回退语义不能简化。

### 验证

完成AC05—AC06、AC27—AC30、AC37。输入台词时按G不会发钱；无选择对象不会猜测；选择三人发10金币，每人各加10。

### 可复制到Codex的任务

```text
只执行阶段5，完成教师后台、可自定义快捷键、完整操作撤销及历史回退。
默认编辑只影响本局，另有保存为模板。奖励目标与当前行动角色分开，多选奖励每人一份。
详细面板自动暂停并保持已有暂停原因；输入文字期间不触发游戏快捷键，长按不能连续发奖。
撤销恢复伤害、消耗、掉落、积分、地图事件、队列、计时和阶段，不仅恢复血量。验证相关验收场景并报告。
```

## 9. 阶段6：正式绘本和公开画面

### 开发范围

- 将阶段0验证的PPTX离线处理集成进正式资料管理。
- 静态页顺序、演讲者备注、导入报告、当前页记忆。
- 教师备注可读、可滚动；公开状态不含备注数据。
- 绘本状态条：姓名、生命、护盾、金币、积分、队伍；没有行动点。
- 自动暂停／返回恢复，视图切换不重置技能、回合或计时。
- 教师在绘本中仍能选角色、发奖、翻页、切回游戏。
- 真正独立的公开渲染，游戏与绘本视图可同步切换。

### 验证

完成AC34—AC36；检查最多7角色布局。观察打开编辑、历史、文字输入、系统菜单和外接屏重连时是否泄露备注。只有真实无线投屏通过，才能标记双画面能力完成。

### 可复制到Codex的任务

```text
只执行阶段6，使用阶段0已通过的方案集成离线PPTX页面和演讲者备注、教师视图和独立公开画面。
绘本状态条严格使用姓名、生命/护盾、金币、积分、队伍；备注只给教师。
进入绘本自动暂停，回游戏恢复原状态与剩余时间；快捷键发奖可用，页码保留。
以实际PPTX和实际无线投屏检查AC34—AC36，未做真机检查的项目保持待验证。
```

## 10. 阶段7：PVP、结算与离线存档

### 7.1 PVP与结算

- 团队战、个人混战的阵营配置与友敌判断。
- 当前生命／护盾／行动点继承，基础点补足，技能次数刷新。
- 最后存活阵营胜，每次击倒对手加2分。
- 主持人积分加入榜单；个人分与当前队伍总分，积分相同并列。
- 提前结束可指定胜者或积分结算，胜者与积分榜分别展示。
- 混战救援限制、全阵营倒地、后台复活等边界。

### 7.2 本地持久化

- 每个完整操作后自动保存，具名手动存档。
- 当前阶段、轮次、队列、暂停／剩余时间、地图事件、物品、积分、技能次数与历史保存。
- 绘本原文件、静态页、备注与当前页纳入备份。
- 模板与存档分开；旧存档使用自己的模板快照。
- 导出完整备份包，断网导入并校验格式、资产与版本。
- 恢复后先暂停；新局重置资产与积分、可重分职业；旧存档保留。

基础自动保存可在前面阶段先加入，本阶段补齐备份、恢复、版本校验与资料完整性。

### 验证

## 11. 阶段8：真机试课与修正

### 11.1 试课脚本

1. 断网，启动并导入／选择绘本，新开一局。
2. 建3名学生与主持人，分不同档职业；随机生成10节点地图。
3. 多选发金币，查看资源变化；探索移动到奖励地点。
4. 开战，暂停口头提问，奖励后恢复；进行移动、攻击和技能。
5. 切到绘本，翻页，看私有台词；发奖，再回游戏继续剩余计时。
6. 模拟一次自然20群体攻击；检查倒地、掉落、积分，撤销再核对。
7. 同节点救援，验证当轮跳过；开放商店，购买、出售和换装。
8. 团队PVP或个人混战，结束显示战斗胜者与积分榜。
9. 保存，退出，再恢复；导出完整包并在测试副本导入。
10. 新开一局，检查资产与分数重置，旧存档仍存在。

另做6学生＋主持人的显示压力检查，和1学生的完整课堂操作检查。
