# 当前开发模式的成品画面预期

当前工程是本地运行的SwiftUI/UIKit原生iPad App，规则/状态在GameCore，公开投影独立窗口；素材和动画数据打包在Bundle。云端Xcode构建只是制作与验证环境，安装后的画面由iPad本机绘制。云端开发本身不会把成品限制成静态表单。

合理目标是完成度较高的2D课堂战棋/电子桌游：原创绘本地图、像素全身角色在节点与道路中移动、镜头跟随/手动查看、视野外方向提示、连续回合轨道、可读的技能/背包、顺滑的战斗侧栏展开与有限攻击/受击/治疗特效。原生组件适合玻璃面板、文字、触控与无障碍；地图可用Canvas或独立2D渲染层实现连续镜头/精灵，但是否加入SpriteKit应由实际复杂度和性能证据决定，不要求推倒现有App。

目前v0.9资产主要是静态人物/怪物画像、节点插画、10实体6状态的图片变换参数和12套8帧特效。画像平移/缩放/旋转能表现反馈，素材本身还没有完整的多方向全身行走/攻击肢体帧。要获得自然的地图人物行走感，需要美术补地图尺度角色和必要方向/状态动画，程序再做镜头、路径播放、同节点错位、侧栏时序与显示关联。只调颜色或把头像移到地图上，达不到完整战棋地图表现。

与经典2D战棋接近的空间阅读与流程反馈可作为本项目目标；具体精细程度由素材质量、动画帧/方向、地图构图、两比例布局和真机迭代共同决定。高规格3D地图、复杂全身战斗演出、骨骼动作、全景电影镜头等，需要另外的资产管线、开发范围和更多制作，不属于现阶段交付。这里不承诺未测设备上的帧率、电视最远阅读距离或无线投影效果。

建议下一版先验证“角色位置+移动+镜头+探索/战斗切换+连续轨道+技能物品栏”的完整显示链路，用已提交结果驱动；再根据实际iPad、16:9/4:3电视和减少动态模式反馈优化。新地图方向/角色动作以独立素材交付，文本、数值与合法性由App画，保留真实规则和原本离线运行/一次结算保障。布局走通、素材审美通过、程序接入通过、真机效果通过应分别记录。

本轮只整理反馈与设计提示词，没有调整App或重新构建IPA；商店缺项已记录，按原阶段3单独推进。
